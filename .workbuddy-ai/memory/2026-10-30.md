# 2026-10-30

## 需求 F：H5 看不到出牌记录 + 牌太小

### 问题拆成两半

1. **出牌区太小**：`--table-card-w: clamp(20px, 5.4vw, 28px)`，390 屏实测牌宽 21px、高 28px，点数只有 7px 高，等于看不见。
2. **过牌没有任何视觉反馈**：服务端处理「不要」时只把 `notUseCardCount + 1` 并移动 `current`，**`round` 不动**。所以有人点了不要，牌桌上什么变化都没有，看起来像卡住了。

### 改动

**1. 尺寸从 CSS `clamp` 改成 JS 按张数算**

`clamp` 不知道这一手有几张牌，只能按最坏情况（20 张）取最小值。改成：

```ts
const need = 1 + (n - 1) * (1 - HAND_GAP_RATIO)
const handCardW = Math.max(26, Math.min(maxHandCardW, Math.floor(avail / need)))
```

| 场景 | 重叠 | 上限 | 390 屏 20 张实测 |
|---|---|---|---|
| 手牌 `isSmall` | 60% | 56px | 43×58（原 34×46） |
| 手牌 `isMobile` | 46% | 64px | 45×60 |
| 手牌桌面 | 46% | 76px | 76×102（不变） |
| 出牌区 | 34% | 手机 50 / 桌面 40 | 单手牌 50×67（原 21×28） |

**2. 「不要」浮标**

前端比对前后两帧的 `notUseCardCount` 差值反推是谁过的牌，弹「XX 不要」浮标，1.8s 自动消失。
两家都过时计数归零，所以多加一条 `prev.notUseCardCount === 1 && cur === 0` 的判断。

### 踩的坑

**坑 1：CSS 自定义属性在「声明它的元素」上求值**

`--card-h: calc(var(--card-w) * 1.34)` 写在 `.page` 上，就被 `.page` 的 `--card-w` 算死了。
在子元素 `.cardList` 上改 `--card-w` 根本带不动 `--card-h` 和 `--card-gap`。
症状：牌宽 50 了、高度还停在 46、间距仍按 34px 算，17 张牌撑到 520px 溢出屏幕（`handCard.x = -65`）。
→ 三个变量必须一起从 JS 传。

反过来说，只要**声明处**的 `--card-w` 已经是最终值，写 `calc()` 就安全：
`.cardList { --card-exposed: calc(var(--card-w) + var(--card-gap)) }` 就是这种（两个变量都是内联写在同一个元素上的）。

**坑 2：点数字号要卡「露出条」不是「牌宽」**

字号按牌宽 0.34 算，「10」宽约 1.1em = 16px，而 390 屏 20 张时露出条只有 17px，
减去左边距后右半截被下一张盖掉，屏幕上显示成「1(」。

```less
font-size: min(
  calc(var(--card-w) * 0.34),
  calc(var(--card-exposed) * 0.72)
);
```

`--card-exposed` 按容器分别给：手牌 `calc(--card-w + --card-gap)`、出牌区 `calc(--card-w * 0.66)`、底牌 `var(--card-w)`。
没声明时 `min()` 兜底 `9999px` → 等价于只按牌宽算，桌面端像素级不变。

大小王的竖排文字（`.joker`）宽度约等于一个字号，也要套同样的 `min()`，否则 17 张牌时超出 1px。

**坑 3：截图里「最后一张牌明显更宽」不是 bug**

手牌重叠 60%，前 n-1 张只露出 20px，最后一张右边没东西盖，整张 50px 全露出来。
看上去像「一张牌宽度异常」，其实是正常的。

### 验证

`h5diag.cjs`（`.screenshots/`）测每个视口：逐张量「点数文字包围盒右端 − 露出宽度」，
正数=被盖住。最终 iPhone13 / SE / Pixel7 / Desktop 全部 ≤ 0，`scrollWidth === clientWidth`，无 console 错误。

| 视口 | 张数 | 牌 | 字号 | 露出 | 最差溢出 | 总宽 |
|---|---|---|---|---|---|---|
| 390×664 | 20 | 43×58 | 12.2 | 17 | -2 | 366 |
| 390×664 | 17 | 50×67 | 14.4 | 20 | -2 | 370 |
| 320×568 | 17 | 40×54 | 11.5 | 16 | -2 | 296 |
| 412×839 | 20 | 45×60 | 13 | 18 | -3 | 387 |
| 1280×800 | 20 | 76×102 | 25.8 | 41 | -10 | 855 |

## 需求 G：新增玩法「跑得快」

### 规则确认（有几处原描述自相矛盾，已跟用户对齐）

| 问题 | 结论 |
|---|---|
| 牌堆「少三张3」但又要「有四个三改判黑桃4」 | 改为**去三张 2 + 一张 A**，四个 3 全留 |
| 裸三张是否随时可出 | **只有这一手打完就出完时**才允许 |
| 只有炸弹能管时是否强制炸 | **必须炸** |
| 顺子/连对/飞机最小长度 | 顺子≥5、连对≥2 对、飞机≥2 组 |

### 实现

- 新文件 `game-ddz-server/utils/pdk.ts`：48 张牌堆、`resolveBanker`（黑桃3→黑桃4 级联）、
  `identifyPdk(cards, handLen)`、`canBeatPdk`、`enumeratePdkAll/Beats`、`hasAnyBeatPdk`
- `app.ts` 加 `mode: 'ddz' | 'pdk'`，`startPdk()` 直接进 play（无叫地主），
  `settlePdk()` 独立结算，`refreshMustPlay()` 下发 mustPlay
- `ai.ts` 加 `decidePdkAI()`：跑牌导向的打分（张数优先、炸弹重罚、单张扣分）
- 前端：大厅 Segmented 选玩法 + 房间列表玩法标签 + 顶栏玩法标签 + 桌面水印按玩法切换；
  跑得快不做本地牌型校验（只维护服务端一份），「不要」按钮读 mustPlay 置灰并变「必须管」；
  结果面板显示三家增减分明细
- 脚本：`scripts/pdk-check.ts`（39 项断言）、`scripts/pdk-e2e.ts`（真实跑完整局，14 项校验）

### 踩的坑

**坑 1：`identifyPdk` 的 `handLen` 不能省**
裸三张的合法性取决于出牌人手上一共几张。枚举 AI 候选时必须传真实手牌数，
否则会把裸三张放进候选池 → AI 出了被服务端拒 → `executeAIDecision` 不重调度 → 整局卡死。

**坑 2：首出判定要用 `lastUser === -1`，不能用 `round.length === 0`**
两家都过之后 `round` 会被清空，用它判断会把「新一轮领出」误当成「本局首出」。

**坑 3：HTTP `/api/addAI` 没有广播**
第 3 人加入会自动开局，但 HTTP 入口只把 room 塞进响应没 `sendMes`。
如果开局后第一个该操作的是真人（跑得快庄家由黑桃3决定，很容易是真人），
没有任何 AI 动作触发广播 → 客户端永远收不到开局帧 → 牌桌卡在准备页。
已补 `sendMes(room)`。**以后新增任何改房间状态的 HTTP 入口都要记得广播。**

**坑 4：炸弹分必须「挂起」，不能一出炸就落账**
规则是「被打掉就没有分」。用 `pdkBomb` 挂起，被更大的炸弹压住时直接覆盖（旧的自然作废），
等这一轮结束（两家都过）或牌局结束才 `commitPdkBomb`。

### 验证

- `pdk-check.ts` 39 项全过（牌堆构成、定庄级联到黑桃5、各牌型、压牌、能管判定、枚举）
- `pdk-e2e.ts` 连跑 4 局全过，14 项校验/局；逐局手算结算分与输出一致
  （示例：赢家 +7 = -10 炸弹 + 17 剩余牌分；炸弹方 +12 = +20 - 8）
- 浏览器（桌面 1280 + iPhone13）：跑得快水印/16 张/无底牌/无叫地主/「必须管」置灰；
  斗地主回归正常（水印、底牌、17 张、叫地主按钮）

## 需求 G 收尾 · 准备面板在手机上被工具栏压住（已修）

**症状**：390 宽屏准备阶段，座位面板右边界 374 > 竖排工具栏左边界 347，面板右下角
盖住「砸番茄」按钮；320 宽屏三个座位被挤成「2 + 1」两行。

**根因有三层**：

1. `.prepare` 是 `position: absolute; left: 50%`，`width: auto` 时可用宽度只有容器一半
   → 三个座位只能竖排。已用 `width: max-content` + `max-width` 兜底。
2. 准备阶段的座位卡没有投掷热区（头像 `PlayerHeader` 只在叫地主/出牌阶段渲染），
   砸番茄/扔鸡蛋这两个按钮在这个阶段是**无效 UI**，却仍占着右下角。
   → 用 `THROWABLE_STATUS` 集合判断，非该阶段不渲染这两个按钮，只留「语音」。
3. 320 屏：座位 `min-width: 76` + `gap: 14` + padding 共 300px > 可用 288px。
   → 加 `@media (max-width: 360px)` 把 `gap` 收到 8、`min-width` 收到 58。

**顺带修的**：选中的道具会跨局残留（准星带到下一局）。
不能在 `useEffect` 里 `setAiming(null)` —— `react-hooks/set-state-in-effect` 会报错。
改成在 WS 消息处理里（`prevStatusRef` 旁边）判断 `!THROWABLE_STATUS.has(data.status)` 时清空，
事件驱动、lint 干净。

**验证**（`.screenshots/prepare-layout.cjs`，四视口）：

|---|---|---|---|

| 320×568 | 288×158（单行） | 36×36 | 0 |
| 412×839 | 380×176 | 38×50 | 0 |
| 1280×800 | 534×186 | 44×58 | 0 |

对局阶段三个按钮（🍅/🥚/💬）都回来了；斗地主模式同样正常。
